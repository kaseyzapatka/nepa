# Deliverable 6 outputs — what to look at

**Client-facing deliverable (the only thing a client sees):**
→ the rendered report `docs/phase2/reports/deliverable06.html`
  (source: `phase2/reports/deliverable06.qmd`; figures embedded from `figures/`;
  four supplemental root-level CSVs read directly by the report — see below).

**Your one QA table (is the machine right?):**
→ `d6_comparison_table.csv` — every candidate with its CE **verdict**
  (new / expand / adopt / contrast), # of CE-shaped FONSIs, the best-matching
  existing CE + agency, the adopt/expand detail, and a rank score. (`07_classify_and_rank.py`.)

**Root-level supplemental CSVs — read directly by the report:**
- `rank_sensitivity.csv` — weight-sensitivity check on the rank score (`07_classify_and_rank.py`'s `rank_sensitivity()`).
- `expand_analysis.csv` — for every candidate category with a matched CE, compares the
  is_ce_shaped FONSIs' size distribution against the CE's stated numeric cap and suggests
  a raised cap (90th percentile of observed values); generalizes the transmission-only
  EXPAND test to all bounded CEs. (`11_expand_analysis.py`.)
- `postfra_recurrence.csv` — per candidate cell, how many CE-shaped FONSIs were decided
  before/after the FRA cut date (2023-06-03); the corpus-answerable slice of the
  post-FRA-refresh question. (`13_postfra_refresh.py`.)
- `threshold_candidates.csv` — deterministic regex retrieval of significance-threshold
  phrases from finding/condition/resource evidence spans (no LLM call). (`14_threshold_retrieval.py`.)

**`figures/`** — 22 PNGs (+ `.rds` sidecars), 20 of which are embedded in the report:
- **Hero:** `fig_d6_coverage_grid` — tech_group × action coverage grid.
- **Sort/keep/rank funnel:** `fig_d6_outcomes_waffle`, `fig_d6_action_distribution`,
  `fig_d6_keep_bounded`, `fig_d6_ce_match`, `fig_d6_sizes`, `fig_d6_classification`,
  `fig_d6_timeline`, `fig_d6_states`, `fig_d6_ce_split`, `fig_d6_adoption_gap`.
- **Analysis 2 (mitigation, corpus-wide):** `fig_d6_mitigated_overall`, `fig_d6_mitigated_share`,
  `fig_d6_mitigation_roles`, `fig_d6_significance_thresholds`.
- **Analysis 3 (existing-CE landscape):** `fig_d6_ce_waffle`, `fig_d6_ce_by_agency`,
  `fig_d6_ce_numlimit`, `fig_d6_ce_bounds_lolli`, `fig_d6_ce_scatter`, `fig_d6_ce_elbow`,
  `fig_d6_ce_upset`.
- `fig_d6_outcomes_waffle.png` and `fig_d6_states.png` are still generated by
  `08_create_figures.R` but are **not currently embedded** in `deliverable06.qmd`
  (`fig_d6_coverage_grid` leads the report instead) — left in place rather than deleted.

**`review/`** — drill-down / QA tables. Open these only when a number in the
comparison table or report looks off:
- `d6_new.csv` / `d6_expand.csv` / `d6_adopt.csv` — the three opportunity lists (full columns). (`07_classify_and_rank.py`.)
- `d6_candidate_evidence_<category>.csv` — per-candidate project-level evidence with citations. (`07_classify_and_rank.py`.)
- `candidate_membership_review.csv` / `candidate_storage_scan_review.csv` — corpus-selection QA (which FONSIs qualify as candidates; storage/text-availability scan). (`01_select_candidate_corpus.py`.)
- `candidate_extraction_review.csv` — deterministic regex/conditions fact-extraction QA. (`03_extract_candidate_facts.py`.)
- `candidate_facts_review.csv` — the LLM-enrichment-backed facts QA that supersedes `candidate_extraction_review.csv` once enrichment is wired in. (`09_wire_enrichment.py`.)
- `candidate_ce_comparison_review.csv` / `candidate_descriptive_review.csv` — CE-match and descriptive-stats QA. (`04_base_rates_and_ce.py`.)
- `candidate_mitigation_boundary_review.csv` — mitigation/boundary-language extraction QA. (`05_mitigation_and_boundary.py`.)
- `ce_landscape_summary.csv` — existing-CE counts per agency. (`06_ce_landscape.py`.)
- `ce_cluster_map_review.csv` — per-CE nearest-neighbor cluster assignments (existing-CE similarity clustering). (`06_ce_landscape.py`.)
- `fonsi_enrichment_coverage.csv` / `fonsi_enrichment_evidence.csv` — LLM enrichment run coverage and quote-verification evidence audit. (`03_enrich_llm.py`.)
- `review/_archived/` — earlier pilot/benchmark runs of the enrichment (`fonsi_enrichment_*_pilot*.csv`, `d6_benchmark_*`, `d6_enrich_benchmark_*`, `ce_verification_worksheet.csv`), kept for provenance and not part of the current pipeline output.

**Not here:** `phase2/data/analysis/deliverable06/*.parquet` are machine-to-machine
handoffs between pipeline steps — you don't read these directly.

**Authoritative review CSVs:** `d6_comparison_table.csv` (verdicts) and the
`d6_adopt.csv` / `d6_candidate_evidence_*.csv` drill-downs are the current client-facing
QA artifacts; the `candidate_*_review.csv` files are per-step internal QA.

**This deliverable is LLM-backed, not deterministic.** Facts, numeric limits, mitigation,
and significance thresholds come from a one-pass enrichment of the FONSIs
(`03_enrich_llm.py`; model **claude-sonnet-4-6**, schema **d6_enrich_schema_v5**,
451/452 FONSIs enriched, ~97% quote verification). `_run.py` wires that enrichment in and
**aborts** if `fonsi_enrichment.parquet` is missing — so the enrichment must be run first.
CE-coverage matches are **candidate matches pending eCFR verification**, not confirmed
coverage.
